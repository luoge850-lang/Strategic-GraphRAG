# Retrieval Baseline Freeze — 2026-09-15

This document freezes the current four-mode retrieval baseline for local
engineering regression. It is a measurement record, not a human-reviewed
answer-quality benchmark.

## Dataset and configuration

- Dataset: `evaluation/silver_retrieval_v1.jsonl`
- Dataset status: `AUTO_GENERATED_SILVER_NOT_HUMAN_GOLD`
- Dataset size and evaluated questions: 37 and 37
- Modes: `vector`, `graph`, `hybrid`, `hybrid_temporal`
- `top_k`: 10
- Bootstrap: percentile bootstrap over question IDs, 2,000 resamples, seed

- LLM anchors: disabled
- Answer synthesis: disabled
- Cross-encoder: disabled
- Comparison unit: canonical filing/page key; paired comparisons use question ID

The complete machine-readable result is

was tuned to improve a particular mode.

## Interpretation boundary

The graph and graph-backed modes score higher on this Silver regression set,
but this does not justify claiming that GraphRAG is generally better than
Vector RAG. The expected evidence pages are generated from the same strict
graph under test, so the benchmark has self-test/construction bias. It is a
proxy for regression detection, not an independent superiority experiment.

The unsupported questions are deterministic and synthetic rather than
human-authored. Page-level matching is not exact EvidenceClaim retrieval, and
bootstrap intervals are descriptive uncertainty summaries rather than
human-gold confidence intervals. With anchors and synthesis disabled, these
results do not measure external LLM answer quality.

## QA decision

Engineering regression can continue without completing human QA: this Silver
baseline is adequate for detecting changes in retrieval behavior under the
same frozen configuration. However, paper-level answer-quality claims and any
independent claim of model or system superiority still require a minimum
human-reviewed Golden QA set.

The historical file `evaluation/golden_qa_human_v1.jsonl` was not modified or
pre-filled. The current claim-ID-v2 worklist is
`evaluation/golden_qa_human_v2.jsonl`; it remains pending until a human fills
and submits each row.
A low-burden next step is to show each question together with its retrieved
evidence first, then ask a reviewer only two initial judgments:

1. Can the system answer this question from the shown evidence?
2. Does the shown evidence support the proposed answer or claim?

The reviewer should record the judgment, reviewer identity, and a short note;
reference answers and detailed grading can be added later for a smaller
publication-quality subset. No labels are generated by this freeze.

## Latency-only follow-up

After the retrieval-only negative-evidence audit was made explicit, the same
37-question Silver benchmark was rerun without changing the corpus, graph,
retrieval parameters, or labels. Retrieval metrics were unchanged; the new
report is `reports/retrieval_benchmark_silver_2026-09-15_latency_optimized.json`.
The observed mean/p95 wall latency changed as follows:

| Mode | Previous mean / p95 ms | Optimized mean / p95 ms |
|---|---:|---:|
| Vector | 33.60 / 60.54 | 57.09 / 123.46 |
| Graph | 2352.61 / 4566.63 | 1624.89 / 2592.52 |
| Hybrid | 4147.22 / 7621.06 | 3349.32 / 5025.02 |
| Hybrid Temporal | 4173.81 / 8259.60 | 3496.11 / 6622.61 |

These are uncached development observations. Graph mean latency improved while
its p95 was statistically noisy; Vector regressed in this run. The safe
conclusion is that Hybrid and Hybrid Temporal improved on this rerun, not that
all modes are universally faster. No database or PDF was changed.
