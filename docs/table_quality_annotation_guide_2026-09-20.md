# 60 条表格候选的独立人工 Gold 标注指南

## 目的

这 60 条记录不是已经完成的答案，而是系统从三份 NVIDIA 10-K 中抽出的候选表格单元格。人工 Gold 的作用是判断：候选记录是否真的被原始 PDF 的表格、表头、脚注和页码支持。它不是让审阅者判断 NVIDIA 财务状况好坏，也不是让审阅者重新计算指标。

## “独立”是什么意思

独立审阅者应先只看问题、原始 PDF 和原文证据，不参考系统预测值。页面默认把系统候选值放在折叠区域；完成初次判断后，才可以展开它做误差分析。不能先照着系统值抄入 Gold，否则只能算“辅助复核”，不能算独立 Gold。

## 每条记录的操作顺序

1. 打开 `http://127.0.0.1:8000/table-qa`，确认顶部显示当前条目编号和进度。
2. 点击“打开原始 PDF · 第 N 页”。页面中的页码只是候选线索；以 PDF 中真正出现表头、行名、数值和单位的位置为准。
3. 先判断“该单元格是否被该页原文支持”。
   - 选“被支持”：PDF 中能同时核对出主体、指标/行名、年份/列名、数值、单位和证据位置。
   - 选“未被支持”：该页没有这项数据、表头与数值对不上、年份错位、单位缺失，或候选把相邻列/行拼错了。
   - 选“看不清，先存草稿”：PDF 模糊、表格跨页无法确认、脚注意义不清。不要猜，保存草稿并写明原因。
4. 如果选择“被支持”，把 PDF 中看到的内容填入 Gold 字段：公司、财务年度、指标/行名、数值、单位、来源文件、页码、表名/章节、行名、列名和原文证据。数值只照抄，不要用计算器改写；括号表示负数时保留括号或负号含义。
5. 如果选择“未被支持”，可以不填写全部 Gold 值，但必须写备注说明原因，例如“页 37 只有 2023/2022 两列，候选年度与列不匹配”。
6. 填写真实审阅者标识。可以使用化名，例如 `reviewer_b`，但同一轮必须保持一致；不能填写模型名。
7. 点击“保存草稿”或“保存并完成 Gold”。只有明确选择支持/不支持并填写审阅者后，才会进入 `HUMAN_REVIEWED`。

## 判断标准

一条记录只有在原始 PDF 中能同时定位公司、财务年度、指标、数值、单位以及对应的表格行列和证据文本时，才标记为“被支持”；只要年份、单位、正负号、行列对应关系或页码无法确认，就不能猜成正确，应标记为“未被支持”或保存为不确定草稿。这里判断的是“这条抽取记录是否被证据支持”，不是判断公司经营好坏。

## 各字段怎么填

| 字段 | 填写方法 |
|---|---|
| 公司 | 从表格主体或章节上下文确认；通常是 NVIDIA，但不要默认填写 |
| 财务年度 | 看表头年份；不能只依据 PDF 文件名 |
| 指标/行名 | 按表格行名填写，避免把相邻行合并 |
| 数值 | 原样抄录；保留括号、负号、小数和零值 |
| 单位 | 从表头或脚注抄录，例如 USD millions |
| 来源文件 | 选择实际查看的 2023、2024 或 2025 10-K |
| PDF 页码 | 填写证据实际所在页，不是候选生成时的猜测页码 |
| 表名/章节 | 表名不清楚时可填章节名或 `UNKNOWN`，并在备注说明 |
| 行名/列名 | 分别抄录左侧行名和顶部列名/年份 |
| 原文证据 | 抄录能证明该单元格的表头、行、列、脚注组合 |

## 不需要做的事

- 不需要评价股票、投资价值或公司好坏。
- 不需要理解所有财务术语；只做“PDF 是否支持这项数值”的核对。
- 不需要修改 Neo4j、图谱、claim ID 或系统预测。
- 不需要把候选值改得更“合理”；无法确认就保留草稿。

## 标注完成后如何使用

完成后，项目会对 Gold 与系统预测分别计算 table-cell accuracy、numeric exact match、unit accuracy、row-level Precision/Recall/F1 和 evidence alignment。标注者只有一人时，这些结果属于单人 Gold 工程检查点；要作为论文级金标准，还需要第二名独立审阅者对相同 60 条重新标注，并对分歧进行仲裁。

当页面显示 `60 / 60` 后，不要手工改 JSON。直接使用工作台保存的同一个队列文件运行：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_table_quality.py `
  --gold evaluation/annotation/table_quality_candidate_2026-09-19.jsonl `
  --predicted evaluation/annotation/table_quality_candidate_2026-09-19.jsonl `
  --output reports/table_quality_gold_2026-09-20.json
```

评测器会自动读取嵌套 `gold` 字段；标记为 `cell_supported=false` 的候选会从
Gold 支持集合中排除，但仍保留在候选分母中，用于反映候选误报。任何未完成的
行都会使命令 fail-closed，不会生成看似完整的论文指标。该结果是候选条件下的
表格质量检查，不是整个 PDF 语料的召回率；要报告语料级 Recall，还必须另外
建立完整表格单元格清单，记录系统漏掉的单元格。
